# Baseline: where the snapshots came from

The snapshots in `snapshots/` are golden masters of **Quick Adsense v2.9.4**, as
shipped. They were generated by the very first run of this suite, against
unmodified runtime code.

## PHP version: 8.4, not 7.4

The plan asks for the baseline to be generated on PHP 7.4. **PHP 7.4 is not
available on the machine that generated it** (`php7.4` does not exist; the
installed versions are 8.2, 8.3, 8.4, 8.5 and 8.6). The snapshots were generated
on PHP 8.4 instead, and the following was done so that PHP 7.4 produces the same
bytes:

* `== notices ==` is normalised (R00 section 5.7): each entry becomes
  `<kind>:<key or stem>@<plugin file>:<line>`, so PHP 7.4 `Undefined index: x` /
  `Undefined offset: 9` and PHP 8 `Undefined array key "x"` / `9` read the same.
  PHP 7.4 `Undefined variable: x` and PHP 8 `Undefined variable $x` also match.
* Deprecations that only newer PHP raises (`Passing null to parameter ...` and
  similar) are not recorded.
* The configs avoid inputs that make PHP 7.4 and PHP 8 diverge. For example a
  non-numeric string in a `position_*` key makes `array_slice()` throw a
  `TypeError` on PHP 8 and only warn on 7.4, so config 19 does not use one.
* The same snapshots, unchanged, also pass on **PHP 8.2, 8.3, 8.5 and 8.6**, each
  running the whole group in a single process. That includes everything that
  depends on `mt_srand()` + `shuffle()` (the random placement), so no
  random-dependent section had to be normalised.

**PHP 7.4 is therefore not yet confirmed.** The CI matrix (PHP 7.4 to 8.4) is
the check: a difference there should be fixed in the normalisation or the config,
not by regenerating the snapshot.

## Other notes

* Running the suite twice in a row (second run in update mode) wrote zero
  files; the tree hash of `snapshots/` was identical.
* Stats are written relative to the day the suite runs and shown as `D-n`. The
  v2.9.4 trimming renumbers numeric date keys, so trimmed arrays are recorded as
  ordered entries (see the README, "Known v2.9.4 behaviour").
* The settings page was rendered without the Classic Editor plugin. The same
  no-op save with Classic Editor active is snapshotted separately
  (`settings-after-noop-save-classic-editor.json`).
